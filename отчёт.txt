1. Заголовок и введение
Название проекта: Веб-форма оформления заказа
Объект тестирования: HTML-код страницы формы заказа (orderForm)
Дата тестирования: 16 марта 2026 г.
Тестировщик: Лихоманов А.И.

Введение:
Целью данного тестирования является анализ предоставленного исходного кода HTML-формы на предмет соответствия стандартам веб-разработки, функциональной корректности, удобства использования (UX) и безопасности.
В ходе работы было проведено моделирование пользовательских сценариев для выявления потенциальных дефектов, которые могут повлиять на сбор данных пользователей и работу интерфейса.

2. Описание процесса тестирования
Были применены следующие техники:
Валидация синтаксиса HTML: Проверка корректности закрытия тегов и структуры документа.
Проверка атрибутов форм: Анализ типов полей (input type), наличия обязательных атрибутов (required, maxlength), имен полей (name).
Анализ пользовательского опыта (UX/UI): Оценка удобства ввода данных, адаптивности и подсказок.
Приоритезация дефектов: Каждый найденный дефект был классифицирован по степени влияния на продукт (Critical, Major, Minor).

Критерии приоритизации:

Critical (Критический): Блокирует работу формы, приводит к потере данных или нарушению безопасности. Требует немедленного исправления.

Major (Значительный): Функционал работает некорректно, возможна загрузка неверных данных, проблемы с отображением на мобильных устройствах.

Minor (Незначительный): Косметические дефекты, нарушение лучших практик кодинга, не влияющие напрямую на функционал.

4. Рекомендации по устранению дефектов
Для повышения качества продукта рекомендуется внести следующие изменения в код:

Критический дефект (ID 1): Добавить атрибут required ко всем ключевым полям ввода (name, phone, email, paymentMethod). Это обеспечит базовую защиту от отправки пустой формы.

html
<input type="text" id="name" name="name" required>
<input type="text" id="phone" name="phone" maxlength="12" required>
<!-- ... -->
<select id="paymentMethod" name="paymentMethod" required>
Значительный дефект (ID 2): Изменить тип поля email с text на email. Это включит встроенную браузерную валидацию формата ввода.

html
<input type="email" id="email" name="email" required>
Значительный дефект (ID 3): Увеличить значение maxlength для поля "Телефон" до 18, чтобы пользователи могли вводить номера в международном формате с кодами стран и разделителями. Также желательно добавить атрибут inputmode="numeric" для удобства ввода на мобильных устройствах.

html
<input type="tel" id="phone" name="phone" maxlength="18" required inputmode="numeric">
(Рекомендуется также сменить type="text" на type="tel" для поля телефона).

Незначительный дефект (ID 5): Оборачивать группы элементов выбора в теги <fieldset> и <legend>. Это улучшит семантику и доступность для людей, использующих скринридеры.

html
<fieldset>
    <legend>Выберите способ оплаты:</legend>
    <select id="paymentMethod" name="paymentMethod" required>
        ...
    </select>
</fieldset>
Незначительный дефект (ID 6): Добавить атрибуты autocomplete к полям формы для улучшения пользовательского опыта.

html
<input type="text" id="name" name="name" required autocomplete="name">
<input type="tel" id="phone" name="phone" ... autocomplete="tel">
<input type="email" id="email" name="email" ... autocomplete="email">
5. Заключение
На текущий момент форма заказа не готова к эксплуатации. Несмотря на то, что визуально форма отображается, наличие критических и значительных дефектов (отсутствие валидации, неверные типы полей) создает высокие риски получения некорректных или неполных данных от пользователей. Это приведет к невозможности обработать заказ, связаться с клиентом и, как следствие, к потере продаж и ухудшению репутации сервиса.

Вердикт: Требуется доработка кода согласно рекомендациям в разделе 4. После внесения исправлений рекомендуется провести повторное регрессионное тестирование.
